# 《敕令》技术架构

> 版本 v0.1　2026-11-08

## 一、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Godot 4.7.2（.NET 版） | 免费、2D 强、导出独立 exe |
| 语言 | C# / .NET 8 | 性能好，本机已装 SDK |
| 渲染 | 像素，32×32 瓦片，最近邻采样 | 像素风必须关抗锯齿 |
| 数据 | JSON（开发期）→ 二进制（优化期） | 可读、可调试 |

## 二、分层

```
src/
├── Core/          纯逻辑，不引用 Godot
│   ├── Sim/       世界状态、时间推进、市民、工作、生产
│   ├── AI/        贵族决策、忠诚、叛乱
│   ├── Data/      定义加载（建筑、资源、性格）
│   └── Save/      存档序列化
└── Godot/         引擎层
    ├── Render/    瓦片渲染、实体渲染
    ├── Input/     鼠标键盘、建造模式
    └── UI/        界面、面板、日志
```

**铁律：`Core/` 不允许 `using Godot;`。**
违反这条，测试和加速模拟全部失效。

## 三、时间模型

- 逻辑 tick：**10 次/秒**（固定步长，不随帧率变化）
- 渲染：60 帧/秒
- 加速：1×/2×/3×/10× 只影响每帧执行的 tick 数
- 暂停：tick 数归零，渲染继续

## 四、市民数据

结构体数组（SoA），连续内存：

```csharp
struct Citizen {
    public int Id, HomeId, WorkId, JobId;
    public short X, Y;
    public byte PathState;
    public float Hunger, Fatigue, Mood;
    public byte TraitMask;
}
```

- 空间索引：均匀网格（Spatial Hash），格边长 8 瓦片
- 渲染只画视口内实体
- 目标规模：2000 市民 / 60 FPS

## 五、寻路

| 场景 | 方案 |
|---|---|
| 去最近某类建筑（仓库、食堂） | **流场** Flow Field，按区块缓存，建筑变动时失效 |
| 点对点长距离 | **A\***，二叉堆 |
| 请求调度 | 每 tick 预算 200 次扩展，超出排队 |

## 六、工作系统

- 全局工作板（Job Board），按优先级排序
- 市民空闲 → 认领 → 预留（Reservation）→ 防止重复认领
- 贵族通过「插活 + 调优先级」间接指挥
- 玩家钦定的活，优先级锁死最高

## 七、存档

- 格式：JSON（gzip 压缩），带 schema 版本号
- 内容：世界状态 + 市民数组 + 建筑 + 官员 + 历史日志
- 目标：≤ 20 MB，≤ 2 秒
- 版本迁移：每个版本写 migration 函数

## 八、本地化

- 所有字符串走 key：`BUILD_HOUSE_NAME`
- 文件：`locale/zh_CN.csv`、`locale/en.csv`
- 运行时切换，无需重启
- **禁止在代码里写任何中文/英文字面量**

## 九、性能预算（硬指标）

| 指标 | 目标 |
|---|---|
| 2000 市民帧率 | ≥ 60 FPS |
| 单 tick 逻辑耗时 | ≤ 8 ms |
| 运行内存 | ≤ 1.5 GB |
| 存档时间 | ≤ 2 s |
| 存档大小 | ≤ 20 MB |
| 启动时间 | ≤ 3 s |

## 十、测试

- 无头模拟测试：跑 10 年游戏时间，检查不变量
  - 资源不为负
  - 市民不卡在不可通行格
  - 内存不持续增长
- 每次改动必跑
